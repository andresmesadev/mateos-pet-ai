# Domicilio de peluquería: dirección, barrio y valor

1. **Funcional:** retirar Zona, Observaciones/mascotas cubiertas y casilla de confirmación del editor. Mostrar Dirección, Barrio y Valor del domicilio. Guardar aplica el importe mostrado; vacío permite conservarlo pendiente y cero significa gratuito.
2. **Casos de uso:** capturar dirección/barrio, usar como valor inicial el acuerdo de mascota si existe, modificarlo, borrarlo para dejar pendiente, guardar y volver a abrir. Mantener modalidades de recogida/entrega/compartido y permisos; conservar registros anteriores de zona/alcance aunque no se editen.
3. **Arquitectura:** reutilizar el resolvedor y endpoint de transporte. El formulario propone una referencia una sola vez por modalidad, respetando cambios manuales y borrado. El valor escrito se envía confirmado al guardar sin casilla; operadores sin permiso no confirman importes. El contrato de confirmación del backend permanece compatible con consumidores existentes. Añadir barrio al borrador, DTO y preparación/persistencia de transporte; sin deducirlo automáticamente desde dirección o zona.
4. **Persistencia:** snapshot opcional `Appointment.transportNeighborhood`, independiente del domicilio del cliente y de notas/zonas históricas. Se limpia junto con los demás datos de transporte cuando el cliente lleva la mascota al centro. No cambia bases de precio, comisiones ni pagos históricos.
5. **Esquema y verificación:** columna nullable aditiva, sin backfill inventado; generar Prisma y aplicar solo a la base local verificada. Jest, lint/build y navegador real para guardar/reabrir barrio, importe propuesto/manual/cero/pendiente, borrador y ausencia de campos retirados. Aplicar todas las migraciones desde cero en PostgreSQL desechable.
